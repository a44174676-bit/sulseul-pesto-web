# 콘텐츠 운영 매뉴얼

## 연락처

`src/config/site.ts`에서 이름, 표시 전화, `phoneHref`(국가번호 포함), 이메일을 수정합니다. 이메일 링크와 문의 제목은 이 파일을 참조하므로 화면별로 수정할 필요가 없습니다. 전화번호를 바꿀 때 표시값과 `tel:` 값을 함께 변경하세요.

## 제품

`src/data/products.ts` 배열에서 제품명·영문명·설명·색상(`cham` 또는 `perilla`)을 변경합니다. 카드는 자동 생성됩니다. 상태 타입은 현재 `개발 중`으로 제한됩니다. 가격·재고·판매 기능은 구현되어 있지 않습니다. 출시가 확정되면 표시사항 및 식품 관련 검토를 먼저 하고 별도 개발 작업으로 전환하세요. 알레르기·원산지·용량·인증 정보를 추정해서 입력하지 마세요.

## 브랜드 문구와 활용법

`src/App.tsx`의 `Home`을 수정합니다. 창업자 조리 경험의 세부 기간·근무처·수상 이력은 제공되지 않아 표시하지 않습니다. 활용법은 일반 아이디어이며 실제 제품 레시피·효능으로 단정하지 않습니다.

## 이미지와 색상

일러스트는 `Botanical`, `Jar`, `food-art`로 직접 작성한 교체용 디자인입니다. 실제 사진을 받으면 `public/images/`에 권리 확인된 파일을 넣고 `<img>`에 적절한 한국어 `alt`, 고정 폭·높이를 지정하세요. 장식 이미지는 `alt=""`로 처리합니다. 제품 콘셉트 안내를 제거하는 것은 실제 사진·패키지가 승인된 후에만 가능합니다.

브랜드 컬러는 `src/style.css`의 `@theme`와 디자인 규칙에서 관리합니다. 외부 폰트·사진을 추가하면 라이선스·개인정보·성능·CSP를 함께 검토해야 합니다.

## 개인정보와 문의폼

문의 방식은 설정의 `inquiry.mode: 'email'`로 명시하며 사이트에 제출 폼이나 서버 수집 경로는 없습니다. 폼 활성화는 단순 스위치가 아닙니다. 운영주체, 수집항목, 이용목적, 보유기간, 수탁자·국외 이전 여부, 권리 행사·삭제 처리, 동의 절차가 확정된 뒤 안전한 서버 처리와 오류/성공 안내, 스팸 방지 기능을 구현해야 합니다. 그전에는 현재 메일 연결을 유지하세요.

## 수정 후 검증과 공개

1. 문구 수정 후 `npm run build`와 `npm run test:e2e` 실행.
2. 360·768·1440px 화면, 모바일 메뉴, 개인정보 링크, 없는 경로를 직접 확인.
3. Git에 커밋하고 `main`에 푸시하면 연결된 Netlify에서 자동 빌드.
4. Netlify 프리뷰에서 확인하고 창업자 승인 후 정식 공개. 현재 검색 차단이 설정되어 있으며 README의 공개 체크리스트를 따라야 합니다.

연락처 값·시각 디자인·문구 변경 후 테스트의 기대값도 승인된 실제 정보로 변경하세요. 테스트를 통과시키기 위해 기능이나 접근성 검사를 제거하지 마세요.
